# 离线固定评价用例

本目录是 E 阶段的**固定输入与离线校验**，不是已完成的研究效果评价。不得将通过 validator 解释成任何模型质量分数或系统通过率。

## 范围和数据

- `manifest.json` 包含恰好 30 个评价任务、1 个独立开发任务、素材与两种固定 prompt 的 UTF-8 摘要。两种条件按同一任务配对；同一任务的材料、全文选区、组织产物（此处均为无）相同。通用提示为 `general-v1`，情景阶段提示为 `contextual-v1`；两者均为这里冻结的离线研究提示，不声称已经接入产品。模型及采样参数必须在真实执行前选择并锁定，不能静默更换。
- 两场景 × 三阶段，每一组合 5 条：材料可用、材料不足、已有正文、条件不同、植入矛盾各 1 条。实际材料是自行编写的 synthetic fixture / CC0，全文是完整范围；`[标识]` 为材料内部唯一锚点，包括末尾证据。它们不是文献、校规、已完成实验或研究结论。不得把模拟文本说成真实文献。
- `system-cases.json` 的系统/安全/并发/恢复用例和 `retrieval-cases.json` 的检索查询与 30 项提示任务分别编号、分别报告，开发任务也不得混入评价集。独立检索语料、top-k=5、相关材料/锚点和无依据问题已固定；BM25、向量及融合的具体实现/版本、嵌入模型和融合参数仍待真实运行前选择并冻结，降级运行单列。无依据问题的行为分母不能混入有依据 Hit@5 分母。
- `rubric.md` 是将来人工判分与安全核查的固定规则，不包含任何实际成绩。

## 本地命令

在仓库根目录运行，不需安装依赖，使用 Python 3.9 或更新版本：

```sh
python -B server/scripts/research_writing_eval/validate.py
python -B server/scripts/research_writing_eval/test_validate.py
```

第一条默认且只能 dry-run：检查清单结构、ID、配对材料及引用、情景/阶段覆盖、输入路径、内容摘要和独立分母，并打印计划与 BLOCKED 状态；第二条在本目录下建立临时副本并清理，运行真实文件篡改与错误清单测试。`--root PATH` 仅用于对独立副本运行相同的离线校验，不是执行开关。正常完成不写结果文件、不访问网络、数据库、`.env` 或用户项目；失败返回非零。

摘要算法：读取每个素材或 prompt 的原始字节，严格按 UTF-8 解码，将 CRLF 和独立 CR 都转换为 LF，再以 UTF-8 编码并计算 SHA-256；不做其他空白或 Unicode 规范化。因此 Git 的 LF/CRLF 转换不影响摘要，内容本身变更会使校验失败。修改素材或 prompt 是更改冻结版本，需明确审核并重新冻结；不能仅更新摘要来掩盖变动。

## 未实现与后续前提

真实执行入口、预算检查/批准、授权测试账号与隔离项目、凭据引用、实际模型及参数选择、版本守卫集成、输出脱敏与存档均**尚未实现或确认**；因此目前不提供任何真实运行命令。计划中的 60 次只是 30 项 × 2 个提示条件的理论单次调用数，不包含重试、开发、检索或系统用例，也不是经批准预算。以后必须获得授权并锁定最终提交、模型、采样、材料和预算，且经过用户确认，才能实现/运行真实入口；应记录失败、受阻、未执行与反例。离线通过不代表 OpenSpec 1.4 或总体验收完成。
