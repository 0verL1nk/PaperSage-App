# 事件驱动写作辅助与多维论文审阅模型

更新：2026-10-04。状态：**已纳入可编辑组织产物、依赖范围和跨章节检查的后续实现基线；不是当前功能完成声明。**

本文回答两个核心设计问题：写作中的 Agent 如何不被固定按钮或少数场景束缚，又不制造持续打扰；论文完成度检查又应覆盖哪些真正影响质量的维度，而不是只检查“逻辑、引用、表达”。

## 1. 定位：开放式规划，不等于无边界操作

写作 Agent 不应被硬编码为“润色按钮”“引用按钮”或几个互不相通的场景。它应能依据论文快照、项目知识、研究蓝图、规范、参考文献范式和用户当前目标，**动态组合 Skill 并规划下一步**：例如先发现一段新增的结论没有证据，再检索项目资料、比较参考论文的结果讨论方式、检查图表/实验材料，最后形成一条可处理的批注。

“可做任何事”的正确工程含义是：Agent 不受固定任务菜单限制，可以组合项目策略允许的 Skill；但工具权限、外部联网、模型预算、稿件写回和远程执行仍必须遵守 `AgentPolicy`、项目权限与用户确认边界。它不会因为“更主动”而静默改写论文、编造实验结论或执行任意外部命令。

## 2. 从事件到建议：开放式 Agent 运行模型

### 2.1 事件不是立即执行任务

每一次变化先生成“分析机会”（opportunity），再由 Agent 判断是否值得运行、应该组合哪些 Skill、是否应合并/延后/取消。这样“任何触发都可以”不会变成每输入一个字就启动一次昂贵的全流程分析。

```text
用户编辑 / 资料入库 / 模板编译 / 阶段变化 / 用户请求
                     ↓
版本化快照与语义差分（WritingSnapshot / KnowledgeSnapshot）
                     ↓
Opportunity：变化性质、影响范围、优先级、关联章节/证据/待办
                     ↓
Agent Planner：选择或组合 Skill，检查权限、预算、冷却时间和重复建议
                     ↓
WritingRun：以版本快照执行
                     ↓
批注 / 资料整理结果 / 待补项 / 审阅发现
                     ↓
按实际依赖检查适用性；用户处理，应用修改另校验当前版本
```

### 2.2 事件来源

| 类别 | 示例 | 常见处理方式 |
|---|---|---|
| 用户显式请求 | “润色本段”“查这句话的引用”“帮我梳理相关工作” | 立即生成任务计划；复杂任务可先说明计划再执行 |
| 稿件内容变化 | 段落新增/删除、章节重组、摘要或结论修改 | 计算文本、结构、主张、术语、引文和 LaTeX 语义差分，形成可合并机会 |
| 知识空间变化 | 新论文/网页/代码/实验资料进入、资料失效、关系更新 | 判断新资料是否影响已有论断、待补项和建议；必要时提示复查 |
| 规范或编译事件 | 模板切换、交叉引用失效、公式/图片/参考文献编译异常 | 规则检查可立即提示；复杂修复作为候选方案 |
| 阶段与过程事件 | 开题、大纲确认、某章完成、全文初稿完成 | 触发更高层次的研究蓝图、结构、证据或审阅检查 |
| 异步维护事件 | 索引完成、资料被归档、后台发现重复/冲突 | 更新知识状态或给出低打扰的整理提示 |

### 2.3 “变化量”应由语义差分决定，不要现在拍死阈值

用户已确认可根据当前稿件与上一个 snapshot 的变化程度触发智能建议。首版不应预设一个僵硬的“新增 200 字就检查”规则，而应提取可配置的 `ChangeProfile`：

- **结构变化**：章节、标题、大纲、摘要、结论或图表位置变化；
- **研究语义变化**：研究问题、方法、主张、贡献、限制条件或结论变化；
- **证据变化**：引用增删、资料失效、实验参数/结果、代码版本变化；
- **表达变化**：术语、缩略语、语气、逻辑连接、段落完整性变化；
- **LaTeX 工程变化**：模板、`.bib`、交叉引用、图表、公式、编译日志变化。

Agent 根据变化的影响范围、当前阶段、已有未处理问题、用户正在专注的任务、预计成本和建议冷却时间决定是否运行。阈值、合并窗口、并发数和每日预算应是项目策略，可由后续测试调整，而不是成为写死的产品承诺。

### 2.4 不打扰与版本正确性

- 一个编辑事件只能产生一个可合并的机会键，例如 `project + document/section + change_class`；
- 运行开始固定输入快照，结果返回时校验项目权限与实际读取依赖；按影响区分 `applicable`（仍适用）、`needs_recheck`（待复查）、`stale`（已过期）；
- 相同问题、同一位置的重复建议应合并；高严重度的编译、学术规范或证据断裂问题可优先展示；
- 用户可设置“专注写作”“仅严重问题”“只在手动请求时提示”等模式；
- Agent 可继续做资料整理或计划，但用户未确认前不能把建议自动写入 LaTeX 工程、研究蓝图或正式引用。

每次运行保存 `RunDependency`，至少包含以下依赖：

| 依赖 | 记录与影响规则 |
|---|---|
| 稿件与章节计划 | 对象/基础版本、实际读取的章节或文本范围、锚点及内容摘要；相关内容改变时待复查，锚点或关键论断失效时过期 |
| 研究蓝图与规范 | 所用字段或规则的 ID、版本与内容摘要；只检查实际使用约束，无法确定范围时依赖整个对象 |
| 原始资料与派生内容 | 原件、证据单元、比较/摘要的版本及派生依赖；原文变化向下传播，核查时回读原文 |
| 检索与集合范围 | 查询、授权来源范围、索引代次、召回配置和候选 ID；资料缺口、路线覆盖等判断还依赖搜索范围，范围内资料变化时待复查 |

任务执行状态、批注处理状态和分析适用性独立记录。运行成功仍可能产生已过期结果；仍适用的分析也不代表候选修改能直接写回。检索索引代次用于重现输入，不将代次变化一律当作所有分析失效；已选原文的版本变化、资料排除/撤权/删除仍须处理。无法确定新增材料是否影响覆盖判断时标待复查，不能以“未读取过”断言无影响。

例如，结果章的标点修改不应使未依赖它的相关工作比较失效；新增与本次查缺范围相关的文献则应让“缺少该路线资料”的判断待复查。全局审阅依赖整个稿件快照，相关结论变化时重新检查受影响关系。

基础稿件发生任何变化后，旧差异不得直接套用；需在当前稿件上生成新候选、展示差异并重新确认，应用时以服务端版本条件校验。来源撤权、删除或排除立即阻止后续检索和生成，已生成内容保留历史记录并提示来源失效。

候选应用前同时校验证据权限、准入和关键依赖。正文版本相同但证据或约束已变化时，须先复查并生成新候选，旧确认不能继续授权写入。批注历史保留快照及处理状态，界面单独显示当前适用性。

### 2.5 批注是写作建议的主呈现形式

写作中的建议应尽量像导师审阅稿件：局部问题以原文旁或边栏批注呈现，而不是反复弹出与正文脱节的提示。`WritingComment` 需绑定 `snapshot_id`、选区起止位置或文档级目标、问题类别/严重度、简要理由、规范或证据引用、处理状态和可选的候选修改；对章节结构、全文引用覆盖等没有唯一文本锚点的问题，使用文档级批注，不能随意挂在某一句上。

聊天界面仅用于解释批注、承接用户追问或主动发起任务，不取代批注作为写作阶段的主要交付面。用户可以接受候选修改、手工修改后解决批注、拒绝、暂缓或继续追问；候选修改必须另经确认。若编辑与锚定选区重叠，或新快照已使批注理由失去基础，批注进入 `stale`，重新分析或人工重新定位后才可继续处理。

### 2.6 可编辑组织产物与下一步

资料理解任务可先提供阅读记录、比较分组和条件差异；章节组织任务可提供职责、论证顺序、材料依据和缺项。用户可调整比较轴、资料、分组及章节计划，后续任务采用新版本。派生候选可自动保存，替换已采用计划须经用户确认；用户直接编辑即为明确操作。

界面按任务呈现“如何组织、为何修改、还需补什么”，优先展示少量可执行步骤并允许展开。资料缺失时给出需补材料与原因；用户已有稿件时直接进入所需任务，不强制重新填写向导或比较表。组织产物与批注均可回查来源，聊天承接解释与追问。LaTeX 模板和编译反馈继续帮助用户处理稿件格式。

## 3. 参考文献既是证据，也是写作范式

参考文献在系统中应有两条严格区分的使用链。

| 使用链 | 要解决的问题 | 输出形式 | 禁止事项 |
|---|---|---|---|
| **证据支持链** | “这条事实/方法/结论是否有来源支撑？” | `EvidenceRef`、原文定位、引用缺口、支持或不支持说明 | 因为句式相似就认定文献支持主张；伪造引用 |
| **结构与修辞范式链** | “同类高质量论文通常怎样组织问题、方法、结果和局限？” | 章节职责、论证推进、贡献表述、图表解释、术语与表达策略的可学习模式 | 大段复刻原句、模仿到近似改写、把范式来源伪装成事实证据 |

例如，Agent 可分析与当前项目相近、来源可靠的系统论文，并提示：“这类论文通常先界定任务边界与约束，再给模块划分和关键数据流；你的系统设计章已有模块列表，但缺少目标—约束—设计选择的因果链。”它也可以给出用户自己的 LaTeX 候选段落，但必须基于用户项目资料重新组织，不能直接搬运原论文措辞。

建议把派生对象定义为 `ReferencePattern`：来源论文/章节/版本、适用论文类型、结构或修辞模式、适用原因、反例/限制、抽取方式与确认状态。它是导航与写作辅助资料，不是可直接引用的学术结论。

## 4. 论文审阅应由 Review Profile 配置，而不是一张万能清单

本科论文与研究生论文、系统设计论文与实证研究论文的要求并不相同。教育部对本科论文抽检强调选题意义、写作安排、逻辑构建、专业能力和学术规范；研究生论文评阅通常进一步重视创新/贡献、方法严谨、数据可靠、研究过程和学术水平。因此系统应根据学位层次、学科、论文类型、研究方法、LaTeX 模板和适用规范包，构造 `ReviewProfile`，决定哪些检查维度必须、可选或不适用。

`ReviewProfile` 可组合：

```text
degree_level + discipline + paper_type + research_method
+ LaTeXTemplate + NormPack + ProjectBrief + available_materials
```

其中 `NormPack` 记录校方/期刊/模板规则及其来源、版本、适用范围和可自动检查项；`ReviewFinding` 则记录每项发现的位置、维度、问题、依据、严重度、置信度、不确定性、建议和用户处理状态。

若保留模型置信度字段，仅供分析和复查排序，不能展示为真实性概率；用户判断应依据定位、材料和检查覆盖范围。

### 4.1 跨章节一致性检查

根据研究蓝图、`ChapterPlan` 和当前稿件建立可回查对应关系：

```text
研究问题 → 方法/设计章节中的回答
设计目标 → 实现材料 → 测试用例/结果 → 结论
正文结果与限制 → 摘要、讨论和结论的表述范围
术语定义 → 各章节实际使用
```

模型提取的关系保存为候选，用户可纠正。章节摘要用于定位需要回读的正文；发现矛盾、重复或证据不足时，回读相关段落与原始材料后形成发现。每条发现关联关系两端的位置、所用材料、理由及下一步，区别“确有冲突”“材料不足”“本次未检查”和“不适用”。

章节变化后更新该章摘要，根据依赖复查受影响关系。审阅不自动改正文，不因全局问题缺少单句锚点而伪造定位。各审阅任务保留已检查、失败、待补和跳过范围，预算不足或部分任务失败不能显示全文检查完成。

## 5. 多维审阅维度库

下表是系统的基础维度库，不要求每篇论文全部启用。它比“给全文打一个分”更符合真实导师评阅和同行评审的方式。

| 维度 | 核心问题 | 系统可做的辅助 | 系统不能替代的判断 |
|---|---|---|---|
| 选题、动机与贡献 | 问题是否明确、有意义，贡献边界是否说清 | 对齐研究蓝图、摘要、引言、结论；提示未定义概念、贡献夸大或贡献—证据断裂 | 判定研究价值或创新性最终成立 |
| 相关工作与引用 | 是否覆盖关键路线，引用是否真正支持，是否区分已有与本人工作 | 论断—引文—原文绑定；提示遗漏路线、只罗列不比较、引用不支持 | 保证文献穷尽或学术事实绝对正确 |
| 研究问题、假设与论证链 | 研究问题、方法、结果与结论是否闭环 | 发现章节间矛盾、无前提结论、绝对化表述和逻辑跳跃 | 替作者决定研究命题 |
| 方法与技术路线 | 方法是否适合问题，设计选择是否被说明 | 结合研究蓝图、参考范式和资料提示缺少理由、假设、边界或流程说明 | 认证方法科学有效 |
| 系统设计与实现 | 模块、接口、数据流、关键实现是否支撑目标 | 用 CodeGraph/代码证据回查论文表述，发现描述与代码版本可能不一致 | 从静态代码断言真实运行行为或架构正确性 |
| 数据、材料与研究过程 | 数据来源、版本、采集/清洗、参数、材料限制是否交代 | 发现材料缺失、版本不明、数据/参数未说明；连接知识项和章节 | 验证数据真实性或代替实验记录 |
| 实验与评价设计 | 对比、基线、指标、环境、样本、参数、重复性是否足以回答问题 | 按系统类/实证类 Profile 提示评价清单和待补项 | 自动运行实验或推导统计结论 |
| 结果、图表与讨论 | 结果是否回答问题，图表是否可读且不误导，解释是否越过数据 | 图表/表格/正文交叉核查；提示单位、图注、对比基准、未解释结果和结论外推 | 断定结果真实或显著 |
| 局限、威胁与适用边界 | 哪些假设、范围和未覆盖场景会影响结论 | 提示未写限制、因果措辞过强、未来工作空泛 | 发现所有局限或替作者承担风险 |
| 可复现性与可追溯性 | 他人能否理解、核查或在条件允许时复做 | 关联代码版本、配置、数据、脚本、日志、图表和论文论断 | 首版自动复现实验或承诺完全复现 |
| 伦理、隐私、权益与学术诚信 | 是否涉及人/敏感数据、授权、知识产权、AI 使用、利益冲突 | 按资料和论文类型触发声明/核查提醒，可标“不适用” | 自动判定合规或替代伦理审批 |
| 结构、表达、术语与 LaTeX 交付 | 章节职责、术语/符号一致性、语言可读性、模板/引用/图表/公式是否规范 | 规则检查、编译日志诊断、跨章节一致性和局部候选修改 | 以机械分数替代整体写作判断 |

系统类计算机论文通常要提高“系统设计与实现、实验与评价设计、结果图表、可复现性”的权重；研究生论文还应更严格检查研究贡献、创新边界、方法/数据严谨性和研究过程记录。对于纯综述、理论或不涉及人类/敏感数据的论文，相应维度应允许标为“不适用”，而不是制造假问题。

## 6. 调研依据与工程推导

下列公开资料影响了维度库的选择，但不直接证明本系统能提升论文质量：

- [教育部：本科毕业论文抽检重点](http://www.moe.gov.cn/jyb_xwfb/s271/202101/t20210107_509029.html)明确本科合格性考察的五项重点：选题意义、写作安排、逻辑构建、专业能力、学术规范。
- [上海交通大学本科毕业论文抽检实施细则](https://www.jwc.sjtu.edu.cn/info/3681/121621.htm)将上述重点细化到研究意义、研究方法、工作量、结构、专业知识/新意和学术不端等可评议点。
- [浙江理工大学研究生学位论文管理要求](https://gradschool.zstu.edu.cn/info/1100/1591.htm)强调充分文献调研、开题与论文内容一致、原始数据记录、格式/研究目标审核、评阅意见修改和学术道德。
- [Nature Portfolio 报告标准与数据/材料/代码可得性政策](https://www.nature.com/nature-portfolio/editorial-policies/reporting-standards)说明研究报告需关注材料、数据、代码和方案的可得性与可复核性。
- [ACM Artifact Review and Badging](https://www.acm.org/publications/policies/artifact-review-badging)将文档化、完整性、可运行性、验证/复现证据作为研究软件与数据工件的独立审查对象。
- [SIGSOFT Empirical Standards](https://www2.sigsoft.org/EmpiricalStandards/docs/standards)与 [SIGPLAN Empirical Evaluation Guidelines](https://www.sigplan.org/Resources/EmpiricalEvaluation/)为系统/实证型计算机研究提供了研究动机、方法、数据、结果、局限、结论和非误导性呈现的细化检查思路。

上述来源与本项目的工程推导是：系统应提供可配置的 `NormPack + ReviewProfile + ReviewFinding`，并将每一条建议与规范、项目资料或参考文献范式建立可回查关系；不得将检查表包装成对论文质量、创新性或合规性的自动保证。

## 7. 验收与测试

除功能与性能外，应验证以下行为：

- 同一稿件的小改动不会触发重复的全局审阅，重大语义/证据/结构变化会产生合理机会；
- 相关变化使分析正确待复查或过期，无关变化保留参考价值；任务完成与结果适用性独立；任何旧差异均不会直接写入新稿；
- 局部建议准确锚定到相应快照的文本；文档级建议不伪装成某个句子的错误，候选修改也不会因批注产生而自动应用；
- Agent 能组合多个 Skill，但每个运行保留权限、预算、工具和证据记录；
- 参考文献范式建议能指出其结构依据，但不输出大段近似原文，也不把范式当作事实引用；
- 不同 `ReviewProfile` 对本科系统论文、研究生论文或不含实验的论文启用不同维度；
- 对论断—证据、图表—数据、实现表述—代码版本、结果—实验材料的连接能给出明确的“有依据/证据不足/不适用”，而不是虚构确定结论。
- 用户修改比较轴、分组或已采用章节计划后，新任务使用新版本，资料缺失不会被生成内容填补；
- 新增检索范围内的相关资料使覆盖或缺口判断待复查，新增无关资料不会作废局部润色；
- 全文检查能定位未覆盖的目标、术语矛盾、重复内容和无结果支持的结论；摘要提示的问题经正文回读确认；
- 用户可直接编辑或审阅已有稿件，不受强制前置表格阻挡；部分检查失败时可见尚未覆盖范围。
