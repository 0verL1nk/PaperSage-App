# Agent 技能与统一知识空间治理协议

更新：2026-09-19。状态：**基于第一、二轮 Grill 的后续实现基线；描述目标能力与约束，不表示当前代码已经完成。**

本文补充 [毕设总体逻辑与决策台账](13-thesis-product-model.md) 与 [AI 写作实现方案](12-ai-writing-design.md)，重点回答三个问题：Agent 如何真正“有技能”、如何自主决定资料是否进入统一项目知识空间，以及代码、实验材料和未来 SSH 执行应如何边界化。

## 1. 已确认的产品决策

1. 面向本科生和研究生等科研新手；二者共用同一条研究—写作—检查主线。
2. 稿件唯一主格式为 LaTeX，用户可上传或选择内置模板；不做 Word 双向编辑。
3. 用户可以请求局部润色、改写或替换候选；Agent 也可主动提出候选，但任何稿件写回都必须由用户确认。
4. 用户只看到一个项目知识空间：论文、网页、代码、实验数据、研究设想、规范、模板、Agent 调研结果和 LLM Wiki 都可存、可读、可检索。
5. Agent 默认可读取当前项目中所有**允许其使用**的知识项；这不意味着把所有文件全文塞进一次模型上下文。
6. Agent 可在项目策略、预算和来源边界内，结合论文主题、研究蓝图、当前任务和资料质量，自主选择本地检索、关系扩展或联网检索，并**自主决定是否入库**；用户保有查看、保留、归档、排除和纠偏权，不需要逐条批准普通资料入库。
7. 第一版实验材料以保存、定位和证据核查为主，不运行实验分析代码或自动生成统计结论。用户 SSH 服务器执行属于后续扩展。

## 2. “理解整个系统”应当被实现为两类上下文

不能只依赖一段长提示词要求模型“理解系统”。Agent 每次运行至少需要两类版本化上下文：

| 上下文 | 回答什么问题 | 典型内容 |
|---|---|---|
| `AgentPolicy` / Skill Registry | **本系统能做什么、何时该做什么、禁止做什么？** | 技能路由、工具权限、来源准入规则、文件策略、预算、超时、输出结构、确认边界 |
| `ProjectBrief` + 项目知识空间 | **这个用户当前研究什么、有什么材料、正在写什么、哪些结论已确认？** | 研究问题、目标、方法、章节、规范、阶段、知识摘要、资料状态、稿件版本 |

前者让 Agent 知道自身能力和边界，后者让它理解用户的真实研究项目。二者均需随版本记录到每一次运行中，不能靠不可追踪的“长期记忆”。

## 3. Agent Skill Registry

一个 Skill 不是模型自由发挥的标签，而应定义触发条件、输入、允许的工具、副作用、停止条件和结构化输出。首版可使用下列技能族：

| 技能 | 何时触发 | 核心输入 | 允许的副作用/输出 |
|---|---|---|---|
| 项目理解与任务路由 | 每次任务开始 | 用户意图、`ProjectBrief`、当前阶段、当前 LaTeX 选区 | 判断进入润色、资料检索、入库、证据核查、代码说明或全文审阅流程 |
| 资料缺口诊断 | 用户卡在研究/写作，或审阅发现证据不足 | 当前主张、章节目标、现有资料与关系 | 返回缺什么、为什么缺、下一步应检索什么 |
| Agentic Search | 本地资料不足且任务策略允许搜索 | 检索计划、研究主题、来源策略、预算 | 本地混合检索、关系扩展、代码/数据读取；必要时联网发现外部候选资料 |
| 资料准入与去重 | 用户上传、仓库导入或 Search 发现新资料 | 候选资料、项目主题、已有知识项、来源策略 | 自动接受、仅保存元数据、延后、拒绝或隔离，并给出可回看理由 |
| 材料理解与索引 | 资料已接受 | 原文件/快照、类型适配器 | 分块、摘要、Wiki、标签、BM25/向量索引、关系候选；派生内容必须回链原件 |
| 证据绑定 | 引用检查、论文建议、代码/实验说明 | 段落、原始资料、可定位证据 | 生成 `EvidenceRef`；证据不足时明确提示待核实 |
| 参考文献范式学习 | 计划、写作或审阅需要借鉴同类高质量论文的组织方式 | 已授权的参考文献、论文类型、当前章节与项目材料 | 生成 `ReferencePattern`：结构/论证/术语/表达策略；禁止大段复刻原文或把范式当作事实证据 |
| 写作建议 | 用户主动请求或受控触发 | LaTeX 选区、论文上下文、规范、证据包 | 解释、局部 LaTeX diff、适用版本；不能直接写回 |
| 多维审阅 | 检查阶段 | 稿件快照、研究蓝图、规范、证据包 | 结构化问题清单、优先级与复查状态 |
| 异步知识维护 | 空闲或资料变化后 | 索引版本、关系候选、失败任务 | 去重、重建索引、更新 Wiki 候选；不得静默改稿或改研究蓝图 |
| 安全与权限守卫 | 始终生效 | 项目权限、来源类型、文件策略、预算 | 约束联网、文件解析、代码、模型上下文和成本；不由模型自行绕过 |

`ProjectBrief`、知识项、规范、稿件版本和任务状态应由服务端装配。Agent 能读完整项目空间，是指它可以按需检索其中任何合规资料；一次运行仍要根据任务选择最小、相关的证据集，避免上下文膨胀和无关资料干扰。Skill Registry 是可组合的，不是封闭场景菜单；事件驱动的机会规划、语义差分、建议去重与 `stale` 处理见[《事件驱动写作辅助与多维论文审阅模型》](15-event-driven-writing-and-review-model.md)。

## 4. Agent 自主入库：判断协议而非黑箱写入

### 4.1 决策原则

自主入库不是让模型获得“任意下载、任意保存、任意作为论文事实”的权限。正确分工是：

- **Agent 作内容判断**：这份资料与研究问题是否相关、来源是否可靠、是否补足证据、是否与现有资料重复或冲突；
- **服务端作硬规则判断**：项目权限、版权/来源策略、文件大小/类型、恶意内容、敏感信息、去重、预算和可访问性；
- **用户保有纠偏权**：可查看入库原因，将资料标为核心、归档、排除，或禁止其用于后续建议；
- **正式学术引用另有门槛**：自动入库只代表可检索的项目资料，并不自动代表该内容已经过学术事实验证或可直接作为正式参考文献。

用户主动上传、明确录入或合法导入的材料属于“用户已加入项目”的事实：通过安全检查后应保留原件/快照，Agent 不能仅因其当前不相关就擅自删除。Agent 可以把它标为低优先级、暂不参与某类建议或建议归档；只有恶意、含密钥/隐私、版权或文件安全风险才进入隔离处理。

### 4.2 状态流

```text
discovered → screening → accepted → parsing → indexed → evidence_ready
                         ├→ metadata_only
                         ├→ deferred
                         ├→ rejected
                         └→ quarantined
```

| 结果 | 含义 |
|---|---|
| `accepted` | 合法原件或快照进入知识空间，可解析和检索 |
| `metadata_only` | 只保留题名、作者、链接/DOI、访问时间和筛选理由；适合版权受限或无法合法缓存全文的资料 |
| `deferred` | 可能相关，但当前主题匹配、元数据或质量不足，暂不进入活跃检索索引 |
| `rejected` | 不相关、低价值、重复、不可核验，保留最小的搜索审计记录 |
| `quarantined` | 疑似恶意文件、提示注入、密钥/隐私泄露、异常压缩包或高风险来源；禁止进入模型上下文 |

### 4.3 决策流程

```text
任务触发
  → 读取研究蓝图、论文阶段、当前章节和项目知识摘要
  → 优先检索项目内已有材料；判断是否存在资料缺口
  → 需要时制定并执行检索计划
  → 版权、权限、文件和风险硬门槛过滤
  → 主题相关性、来源质量、证据可用性、增量价值、时效性与重复性评估
  → Agent 决定 accepted / metadata_only / deferred / rejected / quarantined
  → 接受项解析、索引、建立 Wiki/关系候选
  → 在项目活动流展示“为何入库、依据什么、哪些资料被筛掉”
```

Agent 的判断至少考虑如下维度。数值分数只可用于排序和分流，不能被表述为“资料一定正确”的置信证明。

| 维度 | 应回答的问题 |
|---|---|
| 主题相关性 | 是否直接服务于研究问题、方法、章节目标或当前证据缺口？ |
| 来源质量 | 是否来自同行评审论文、出版社、权威机构、官方文档、可信代码仓库或可追溯实验记录？ |
| 证据可用性 | 是否存在可定位的原文、方法、数据、结论、版本或代码符号？ |
| 增量价值 | 是否补足资料、提供反例/不同路线，还是只重复已有内容？ |
| 时效与版本 | 是否过期、被替代，或与当前技术/规范版本冲突？ |
| 版权与隐私 | 是否可保存、索引并向模型传递必要片段？ |
| 任务匹配 | 当前任务是润色、综述、系统实现还是实验核查？不同任务阈值不同。 |

## 5. 项目知识空间的数据与证据约束

用户面对的是一套知识空间，内部建议至少记录以下对象：

```text
KnowledgeItem      # 统一的用户可见知识项
AssetVersion       # 文件/网页/仓库/稿件的具体版本或快照
EvidenceUnit       # 文档分块、网页片段、代码符号、数据字段、实验记录等
KnowledgeRelation  # supports / contradicts / defines / uses / evaluates / implements / cites
IngestionDecision  # Agent 对候选资料的判断过程与结果
EvidenceRef        # 某条写作建议所实际使用的原始证据定位
ReferencePattern   # 参考文献中抽取的结构/修辞范式，不能充当事实证据
NormPack           # 校方/期刊/模板规则及其来源、版本、适用范围
ReviewProfile      # 按学位、论文类型、方法和材料组合的审阅维度配置
ReviewFinding      # 有位置、依据、严重度、建议和处理状态的审阅发现
```

`IngestionDecision` 不应只被压成一个“入库状态”，至少应保存：触发来源、检索计划、工具与预算、`AgentPolicy`/Skill/模型版本、研究蓝图版本、来源 URL 或 `repo@commit`、内容哈希、重复目标、质量判断、决定、机器理由、人工覆盖、解析与索引结果。

LLM Wiki、摘要、标签和关系图均是派生知识；它们帮助读、找和组织，但不能取代原始文献、网页快照、代码版本和实验记录作为正式证据。

## 6. Agentic Search 的自主性与边界

Agent 默认读取整个项目的合规知识，并根据当前主题、论文阶段、章节和证据缺口决定：先做局部混合检索、关系扩展，还是在项目策略、预算和来源边界允许时再做联网调研。联网结果需要保存检索词、筛选理由、URL、访问时间和网页快照/元数据，然后由“资料准入与去重”技能自行判定是否纳入。

以下内容不可因“自主性”而被自动下载或信任：受版权/订阅限制全文、来源不明的聚合转载、无原始来源的 AI 生成材料、带有提示注入/恶意文件特征的内容、含密钥和隐私信息的代码或数据。对于这类来源，Agent 可保留元数据、提示用户提供合法副本，或直接隔离。

## 7. 代码和实验材料

### 7.1 代码入口与 CodeGraph 渐进路线

代码统一作为知识空间中的 `KnowledgeItem`，支持三类入口：本地目录、ZIP 包和 Git 仓库地址。三者最终都固定为一个不可变的仓库快照，记录来源、哈希或 commit、目录清单、解析状态和权限。

- 本地目录：客户端应显式选择目录并建立快照，不读取未选择路径；
- ZIP：执行大小、文件数、路径穿越、压缩炸弹和敏感文件检查后解包；
- Git 地址：先支持公开仓库；私有仓库须经过用户显式授权，不能把密码或长期私钥写入日志。

首版不执行代码。它可提取目录、README、关键模块、文件/符号定位和导入关系，给论文“系统设计与实现”章节提供可回查依据。更深层的路由/接口/调用链 CodeGraph、跨材料关系图和运行时推断按 P1/P2 推进。

### 7.2 实验材料：保存和核查，不代替实验

首版将原始数据、参数配置、分析脚本、结果表、图片、日志和说明文档作为可版本化资料保存，关联论文段落和章节。Agent 可以帮助发现“实验描述缺参数”“图表没有对应数据”“结果段缺证据”等问题。

首版不运行脚本、不自动得出统计结论、不把模型推断写成实验结果。不能复现或证据不足时，正确输出是“建议补充/复核实验”，而不是编造结论。

### 7.3 SSH 执行是后续受控扩展

未来若连接用户 SSH 服务器，应采用“用户确认的远程实验连接器”，而不是给 Agent 一个通用终端：

```text
Agent 识别运行需要
→ 生成 ExecutionProposal（脚本/数据/参数/预期输出/资源限制）
→ 用户确认
→ 服务端生成结构化 JobManifest
→ 受限 SSH 执行器或用户侧 Runner 执行预注册任务模板
→ 收集白名单产物，作为候选知识项返回
```

此能力不进入 P0 验收。禁止 Agent 直接执行任意 shell 命令、使用 root、拼接未校验参数、持久保存密码或私钥、开放端口转发或误报 SSH 断连后的任务成功。后续设计需包含主机指纹确认、最小权限账号、独立运行目录、作业 ID、超时/资源上限、脱敏日志、输出白名单、失败/未知状态恢复和取消语义。

## 8. 可测试的验收点

本系统应验证“治理协议是否有效”，而不是抽象宣称 Agent 很智能：

- 给定不同相关性、来源质量、版权状态和重复程度的资料，自动准入决定是否符合预设策略；
- 自动入库后，是否能回溯到原始来源、版本和决策理由；
- 重复资料、过期版本、提示注入文本、含密钥代码包是否被正确降级、拒绝或隔离；
- 论文建议能否回到原始 `EvidenceRef`，而不是只指向 AI 摘要；
- 用户排除某资料后，后续检索和建议是否不再使用它；
- 稿件变化后，旧版建议是否标记为 `stale` 而非写入新稿；
- 实验资料缺参数、图表缺来源或结果描述无证据时，审阅是否能给出可定位的待补项。
