## 范围与方法

## 本轮之后仍未解决

- **PostgreSQL 连接恢复**：单连接访问门消除了本进程内的 `conn busy`，但连接被取消/断网后关闭时不会自动重建；是否改用 `pgxpool` 及关闭顺序尚未实现。
- **索引状态可见性**：索引失败仍只写日志，没有逐文档状态或重试入口；检索空结果不能证明资料未入库。
- **永久删除与版本化**：0022 的 `RESTRICT` 仍会阻塞项目永久删除；跨 R2/Neon/DB 的安全清理、写入屏障与恢复语义未实现，当前只能显式失败。
- **旧部署停写**：旧 Vercel API 仍可能写入对象存储；新的 LaTeX 对象键只解决新建冲突，不能证明跨实例安全。
- **真实环境验收**：真实 PostgreSQL/MySQL/TiDB、R2、Cloudflare 回源、真实模型/嵌入/邮件、浏览器端编译与端到端 SSE 尚未完成。
- **跨标签设置**：模型选择已原子化，但完整 `providers` 列表编辑在标签页之间仍是最后写入覆盖。
- **大历史资源**：会话与文献列表已不设条数截断，超大会话/资料集的内存、带宽和模型上下文成本尚未测量。
