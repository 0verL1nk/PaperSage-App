## 5. 实现要点备忘（本轮勘察结论，已验证）

### Agent 面板（tasks 7–9）

- SSE 协议（`server/internal/agent/service.go`）：`data:` 行 JSON 事件 `{type: meta|delta|tool_call|tool_result|error|done}`；POST `/api/v1/projects/:project_id/agent/chat`，body `{conversation_id?, content}`；EventSource 不支持 POST + header，前端用 fetch + ReadableStream 解析。
- 会话 API：`GET /projects/:id/agent/conversations`、`GET /agent/conversations/:id/messages`、`DELETE /agent/conversations/:id`。
- 坑：messages 接口的 `toolEvents` 是 **JSON 字符串**（DB JSON 列经 `*string` 扫描），前端需 parse；工具活动按「同名队列」配对 `tool_call`/`tool_result`（SSE 协议未含 call id）。
- 未配置模型：chat 返回 400 envelope（info 为中文引导）→ 面板展示「去设置」入口。
- 现状证据：`WritingPage.tsx:646` 的 `AIPanel` 是静态占位；`frontend/src/services/` 无 `agent-api.ts`；全前端无 SSE 代码。

### 工作台底座（writing-workbench-foundation）

- 后端模式：参考 `server/internal/documents`（`verifyProjectAccess` + camelCase DTO）与 `server/internal/projects`（`projects.go` 单文件域 + `Mount`）。
- SQL-first：先改 `server/schema/tables/*.sql`；migrations 0011 双方言（postgres/mysql）；`AllModels()` 注册（SQLite AutoMigrate）；`make generate-dao SCHEMA_DSN=...`（需数据库环境）。
- 契约：envelope `{code,data,info}`；路由级 404 是裸 `{"detail": ...}`（历史兼容）。
- 前端：URL 只在 `api-routes.ts`；新域新建 `<domain>-api.ts` + 测试 + barrel 导出；query key 建议 `['writing-state', projectId]`。
- e2e 需后端 + MinIO + seed（见 CLAUDE.md「End-to-End」）；mock 模式与 helper 见 `frontend/tests/e2e/helpers.ts`。
