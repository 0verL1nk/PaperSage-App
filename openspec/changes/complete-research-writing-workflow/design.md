## Goals / Non-Goals

**Goals**：覆盖本次 P0/P1/P2 盘点，交付“材料→研究蓝图→比较/章节计划→有据建议→确认保存/编译→审阅→复查”的可验证闭环；用户也能从已有稿件直接开始。

**Non-goals**：重写技术栈、通用工作流引擎、增加必需 Redis/数据库/容器服务、重建编译器、完整 Graph RAG、远程实验执行、模型训练、Word 编辑、自动判定论文真实性/创新性。AI SDK/AI Elements 只作为减少维护负担的实现选项，不代替功能验收。

## Decisions

### 1. 总控 + 五个子变更，而非一次性重构

总控仅定义整体验收和任务映射；领域契约、实现设计与细粒度任务在子变更中维护。每个子变更可以产生多个小 PR，达到自己的验收门后单独归档；总控必须等五个子变更及真实集成证据齐全后归档。没有把 P1/P2 从目标删除。

| 顺序 | 子变更 | 依赖 / 放行条件 |
|---|---|---|
| A | `production-release-readiness` | 先解决 PR40/迁移、现有功能部署与真实连接；不借此宣称新业务已完成 |
| B | `versioned-content-and-evidence` | A 的基线可信后实施；CAS 启用前必须协调旧 API 停写和前端升级 |
| C | `research-organization-artifacts` | 依赖 B 的版本、定位及权限；可提前实现纯 UI/schema，但不能以 mock 代替集成完成 |
| D | `evidence-aware-writing-review` | 依赖 B/C 的固定输入与产物；规范条目可并行，审阅与自动触发最后集成 |
| E | `research-writing-quality-closure` | 数据集/验收脚本可在 B–D 并行准备；真实效果、性能及最终发布在集成后完成 |

### 2. 复用底座，优先保护用户内容

仍由 Eino prebuilt DeepAgent 编排受控领域工具和声明式子 Agent；不自行复制其任务规划、SSE、Run 或审批框架。普通派生分析允许保存；AI 替换已采用计划、研究事实和稿件须用户确认。用户直接编辑是明确操作，但仍受版本与权限检查。

所有新能力使用项目归属、不可变输入版本、明确终态和幂等键；“执行成功”“内容已保存”“分析仍适用”“论断已核验”分别记录。故障注入与真实数据状态断言优先于仅断言 mock 被调用。

### 3. 内容与数据模型的唯一权威

来源版本、稿件 CAS、跨库索引和证据兼容见 [内容底座设计](../versioned-content-and-evidence/design.md)。组织产物和审阅分别引用这些版本身份，不复制一套原文/稿件存储，也不使用聊天文本充当正式研究事实。

新模型关系、唯一键、外键、软删与级联含义先在对应子变更中核对并绘制 ER，再同步 `server/schema/tables`、两方言迁移、Go 模型和必要 DAO。禁止只放松 schema drift 测试来掩盖不一致。

### 4. 成本、隐私和权限

自动分析默认手动模式；显式启用后才允许事件机会触发模型调用，并使用合并、去重、取消与已授权预算，不按固定字数/轮数截断任务。资料与工具输出是数据，不能扩大权限。向第三方模型发送资料前说明范围；不把 API key、DSN、完整私有资料写入验收报告。

真实模型对照评价需使用获授权的模型和材料，并在运行前确认费用预算；不具备条件时可完成脚本和本地测试，但真实评价任务保持 `blocked`。

### 5. 独立发布与真实证据

前端 Vercel、API 静态二进制+systemd+Caddy、云库/R2、浏览器编译保持不变。既有发布 helper/health/校验和是唯一发布路径，不绕过 CI、不覆盖标签、不执行 schema down。首次 DNS/证书切换及旧 API 停写必须在本机健康与兼容验收后执行。

正式记录放在 `docs/verification/research-writing/`，包含提交/版本、环境、输入规模、配置、结果、原始输出索引、失败/未执行原因与秘密脱敏说明。仅“README 写了支持”“模型回答顺畅”“HTTP 200”不算闭环验收。

## Risks / Trade-offs

- 范围大：用独立 capability、小 PR 和子变更验收控制；总控不因部分交付就标完成。
- 主库、Neon 向量库、R2 不存在分布式事务：先准备不可变对象/代次，再以主库指针提交，失败保留旧活动版本并补偿清理。
- 旧客户端/旧 Vercel API 可能继续原位覆盖对象：未证实停写前不得激活版本化写入。历史被覆盖的内容不能凭空重建。
- 索引或模型降级：显式记录实际模式；不得混入完整语义检索评价。
- 外部阻塞：凭据、DNS 控制、实际收件、授权模型/预算及真实材料分别设置证据门，不能用占位值或模拟结果勾选。
- 生产 schema 迁移/对象回填具有风险：先隔离测试与恢复方案，新增兼容迁移优先；回滚程序必须已证明与现有 schema 兼容。

## Verification Strategy

1. 每个子变更按 Requirement/Scenario 建立代码/测试/人工证据映射；先写能因真实回归失败的测试。
2. 运行当前 Go/前端静态检查、单测、race、PG/MySQL 隔离迁移和针对性 E2E，不降低48%覆盖率门禁；逐步增加关键路径覆盖，不用覆盖率代替效果评价。
3. 使用两种场景、三阶段的固定项目完成保存/索引/检索/产物/确认/编译/审阅/恢复；加入越权、并发、断流、取消、源失效和故障注入。
4. 完成固定提示与检索对照、开发者走查和小服务器性能记录；失败和未执行保留，安全主路径缺陷不能被总体通过率抵消。
5. 子变更严格校验并归档；总控核对全部任务、真实上线证据和未解决阻塞后再归档，不修改历史 archive 冒充完成。

## Approval and Execution Boundary

当前产物为拟议规格，不是实现或上线完成声明。先审阅这组 OpenSpec 及实施顺序，再开始业务代码、生产迁移、发布/DNS变更；实施中发现无法从代码/现有授权解决的外部条件，应只阻塞相应任务，并完成其余独立工作。
