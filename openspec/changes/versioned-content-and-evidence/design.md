## Context

复用 `FilesService`、`AgentChangeProposal`、`persistRunEvidence`、`RagIndexGeneration` 和现有Run事件。需修复原位覆盖、忽略DB错误、确认校验与写入之间竞态、48KB/PDF局部读取限制及旧索引跨代污染。历史`source_version`字段为摘录哈希，不能静默改解释为完整来源版本。

## Goals / Non-Goals

目标是完整处理、稳定版本/定位、CAS保存/恢复、代次与失效闭环。不是取消所有上传/解压/内存安全边界，不把全部全文塞进模型，不新增OCR/队列平台或另一套Run。

## Data Model and Relations

| 关系/记录 | 约束与职责 |
|---|---|
| Project 1:N ProjectSource | `project_sources`为稳定来源身份；Document/LatexFile各映射一个来源，不迁走现有资产归属/软删逻辑；新规范/产物可复用来源身份 |
| ProjectSource 1:N SourceVersion | `source_versions`保存不可变对象键、原始完整字节SHA-256、单调修订、创建者/时间；`UNIQUE(source_id, revision)`，当前版本为来源指针，恢复指向历史版本但创建新修订 |
| SourceVersion 1:N SourceExtraction | `source_extractions`绑定抽取器版本、完整文本对象/摘要、处理状态与错误；完成的抽取结果不可原位改写，同源重抽取有独立身份 |
| SourceExtraction 1:N SourceSegment | 稳定原文区间/物理页/段落定位；索引chunk引用抽取结果/来源修订和代次，不以可变片段序号充当永久位置 |
| RagIndexGeneration -> SourceVersion清单 | 构建manifest、配置/维度、进度与终态；唯一chunk键含代次，PG/Neon两条路径一致 |
| AgentEvidence -> SourceVersion/Extraction | 新增可空`source_revision_id`和定位身份；既有摘录摘要字段保留原语义，旧记录明确legacy/unverified |
| Proposal/RunDependency -> 输入版本 | 候选绑定稿件修订和证据/规范依赖；记录跨对象的实际依赖，不能只存聊天文本或模型给出的ID |

稿件修订复用`SourceVersion`，不另存一套正文；`latex_files`的现有key/hash/size为兼容读取投影，必须随来源当前指针同事务更新，不能有两个可独立写入的真相。项目内关系用外键、唯一键及必要的项目复合键约束；领域资产软删仍显式处理子行，基础设施记录不机械套软删。实施阶段先绘ER与回填顺序，再落SQL truth/PG/MySQL/Go模型。

## Decisions

### 1. 完整抽取与有界续读

移除“抽取成功但正文被截断”的路径，包括PDF内部LimitReader只读部分却报成功。允许的文件必须完整抽取；超过已说明的资源安全边界时明确失败/不完整且不激活索引。原文与抽取结果保存摘要和完成状态。长任务取消、失败和重试可查，扫描件无可抽取文字时不伪造OCR结果。

读取响应包含来源修订、抽取身份、定位计量单位、完整性状态、当前范围、下一游标或结束。采用UTF-8字节区间并校验Unicode字符边界；前端Monaco UTF-16选区显式转换，不能直接混用。PDF定位为物理页；DOCX/TXT为段落/文本区间，不冒充印刷页码。模型工具按需续读并声明剩余范围，不自动把全文接入上下文。

### 2. 保存/建议/恢复的事务边界

先上传新的不可变对象并验证摘要；随后在单个主库事务内登记版本、CAS切换当前指针、更新文件投影及候选终态。基准不符409、缺条件428、对象或DB失败不报成功；缓存仅在提交后失效/更新。多文件候选先准备所有对象，全部CAS成功后一起提交，不暴露部分应用。

恢复是复制历史内容形成新修订；原历史保持可读。幂等键绑定项目、操作、基准与内容摘要，重复请求不制造新版本。未引用对象先登记待清理，重试回收前重新检查引用；不得直接套用历史分支的运行时逻辑，历史清理表仅在语义/约束合适时复用。

### 3. 索引跨库一致性

来源当前版本变化产生持久处理状态；有限后台worker恢复/重试确定性工作，复用来源状态和代次表，不新增中间件。模型任务仍在现有Run中，进程崩溃不自动宣称恢复任意LLM执行。

索引构建写入新代次/配置/来源manifest；旧代次在构建失败时仍可查询，但返回其真实版本并标明是否过期。Neon准备完成且数量/摘要/权限校验通过后，主库CAS激活；所有检索路径先读取主库活动代次与来源权限，再按精确代次查向量/词法数据。切换前发现并发资料变化则拒绝激活并重建/复查；主库不可读时不从缓存/向量库直接放行。延迟清理旧代次不影响当前查询。

### 4. 来源失效不是事后删缓存

主库决定读取权限与是否允许用于新分析。排除的来源停止参与生成，但有读取权限的用户可看带“已排除”标识的历史；失去读取权限时，证据/工具输出/依赖消息以失效占位代替，不能从SSE重连、缓存或派生产物绕回原文。已经发送到模型/客户端的数据不能撤回，界面明确此边界。

相关派生物标记needs_recheck/stale；来源不可用立即阻止新生成/旧候选应用，不等待R2/Neon清理。Run返回结果前再校验；来源更新后仍能读其授权历史，不等于允许以旧版本冒充当前事实。清理只处理已确认无引用对象/旧代次。

### 5. 接口与调用方

沿用项目级鉴权与信封：内容GET返回当前修订/ETag；PUT支持`expectedRevision`或强If-Match（两者同时提供须一致）；列表/GET历史和恢复端点归属校验。旧读取仍可用；激活后旧无条件写入返回428和可恢复提示，不以“最后写入者赢”兼容。

增加来源版本/处理状态、分页原文和定位查询；`agent.read_document`/检索结果提供可续读身份。前端自动保存、手动保存、导入、AI应用/恢复及编译都使用相同内容服务。AI来源ID和游标是非可信输入，服务端重验身份/权限/区间。

### 6. 编译绑定真实输入

编译manifest绑定每个输入文件的修订或草稿内容摘要、引擎和资源profile。编辑中草稿可本地编译但标明未保存；已保存结果只有manifest仍匹配当前稿件时标记为最新。资源读取不能在执行中偷偷换成最新文件；旧结果保留其版本信息，不自动覆盖当前PDF状态。

## Migration / Rollout

1. 先合并迁移历史并将当前版本测试改为兼容后续增量，不把schema21当永久head；只在隔离实例回归。
2. 添加可空关联/新表、兼容读取、版本元数据与新条件写契约；独立工具对旧对象校验并创建当前基线，不在SQL迁移中访问R2。
3. 发布新前端/全部调用方，记录旧Vercel API与直接域名停写；无法证实停写则不激活版本化写入。
4. 在受控写窗口重核摘要、完成剩余基线并启用CAS。旧不可恢复历史标记unknown，不由当前内容推造。
5. 保留旧读取投影直到调用方/恢复验证完成；不自动删列/删除旧对象。程序回滚只允许兼容当前schema与CAS的版本，不能重启无条件覆盖服务。

## Verification

长于48KB且关键证据在末尾的中英文资料、PDF后页、UTF-8续读拼接与取消；原文定位无法验证时的诚实降级；并发保存/恢复/审批、DB/S3故障、幂等/孤儿回收；跨代chunk隔离、失败保旧、并发增删/激活、向量延迟/故障、缓存跨实例与SSE失效；旧证据不冒充新版本；草稿/已保存/过期编译manifest。三方言模型一致性、PG/MySQL隔离迁移及必要E2E均须执行，禁止对生产库运行建删测试schema。
