## Context

已有静态二进制+systemd+Caddy、受限部署用户、SHA-256、独立migrate、精确version/commit健康校验和失败恢复。PR40补齐已在云库执行的19–21迁移；服务器最近仍未激活，向量库认证失败。当前证据不足以宣称已上线。

## Goals / Non-Goals

完成现有功能真实上线和恢复验证；不增加Docker/Redis/本地数据库/TeX Live，不重建CI或改用第三方任务平台。

## Decisions

1. **唯一发布路径**：合并PR40后核对main/迁移/CI，稳定SemVer标签触发现有Release。产物来自同一run并核对checksum，服务器只运行API和Caddy；正式进程不启动迁移。
2. **配置预检**：只读核对主库和直连迁移版本/dirty/结构、R2权限、应用认证密钥连续性和模型/邮件来源。只从已有授权凭据修复向量DSN；不重置数据库角色密码影响其他客户端。
3. **切换顺序**：新实例回环健康→获授权的验证项目业务检查→HTTPS/安全组→DNS→Vercel前端真实闭环。切换前保存旧路由/版本信息；版本化内容阶段启用前再证明所有旧API入口停写。
4. **真实模型**：用户模型配置、管理后台、env解析顺序保持；使用获授权测试账号和模型进行最小真实交互，记录首字/最终终态，断流与取消分别验证。没有授权模型时该任务受阻，不能把生成器替身算真实验收。
5. **恢复**：仅回滚已证明与当前schema兼容的程序；首次无旧版时明确失败并保持停止。只在隔离环境注入故障，生产不为演练破坏数据库或正在进行的用户任务。
6. **外部证据**：R2 HEAD不等于写入成功；实际新建/下载/删除仅针对专用测试对象。邮件provider接受/投递事件不等于用户实际收件，需测试收件箱或用户确认。验证账号/对象可按事先约定清理，不触碰用户项目。

## Verification

复用现有CI、发布helper回归和PG/MySQL隔离迁移；实际核验`/health`元数据、TLS、CORS、SSE逐段到达、local/online/custom目标一致、真实保存/编译/历史。记录资源使用基线和失败项，报告路径为`docs/verification/research-writing/release-readiness.md`，不保存秘密。

## Migration / Rollout

本变更不引入额外schema。若预检发现新的schema领先或不兼容，不force或覆盖标签，先开最小修复。DNS和旧API停写为显式操作记录，不能由普通PR自动执行。阻塞项不影响其余独立验证，但未解除不能归档。
