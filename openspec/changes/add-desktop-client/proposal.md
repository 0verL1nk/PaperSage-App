# add-desktop-client

## Why

PaperSage 目前只有浏览器形态。用户在本地写作时需要自己开浏览器、记地址、管理下载目录；浏览器标签页容易被误关，编译和 Agent 长任务在切走标签后也没有系统级反馈。

直接把 Web 页面装进桌面壳只能得到“没有地址栏的浏览器”，不构成客户端。我们需要的是原生外壳行为：单实例、窗口状态、原生菜单、托盘、系统通知、本地文件对话框与拖放、深链，以及可持久化的 API 目标。

## What Changes

- 新增 `desktop/` 独立 Go 模块，基于 Wails v3.1，复用现有 `frontend/` 构建产物，不重写业务 UI。
- 原生外壳：单实例、窗口状态恢复、应用菜单与快捷键、系统托盘、关闭到托盘、上次路由恢复。
- 原生集成：文件/文件夹对话框、系统拖放、桌面通知、`papersage://` 深链、外部链接交给系统浏览器。
- 本地工作区：导入本地文件夹、导出项目到文件夹、在文件管理器中显示、远程/本地 API 目标持久化与显示。
- 本地运行时：由客户端托管本地 Go 后端进程（启动、健康检查、优雅退出、崩溃重启）；编译继续使用项目自带的浏览器 WASM 引擎，不依赖也不检测用户本机安装的 TeX。
- 本地目录同步：项目可绑定本地文件夹，LaTeX 源文件在应用与磁盘之间双向同步；冲突时显式确认，不静默覆盖。
- 交付：可重复构建、版本元数据、Windows 安装包；基于 GitHub Releases 的自动更新（检查、下载、校验、替换、重启）。
- 品牌资产：桌面图标、安装包图标与托盘图标统一使用现有 `frontend/public/favicon.svg` 品牌标识，不另画一套。
- 仓库布局：顶层 `desktop/` 独立模块，采用标准 Wails v3 结构；不改动 `frontend/`、`server/` 的既有分层。

## Capabilities

### New Capabilities

- **desktop-shell**: 单实例、窗口状态、原生菜单与快捷键、系统托盘、启动恢复与桌面环境识别。
- **desktop-native-integration**: 原生文件对话框、系统拖放、桌面通知、深链、外部链接与安全边界。
- **desktop-local-workspace**: 本地文件夹导入、项目导出、文件管理器定位、API 目标持久化与离线反馈。
- **desktop-local-runtime**: 本地后端进程托管、版本与生命周期管理、不依赖本机 TeX 的编译路径。
- **desktop-local-sync**: 项目与本地文件夹的双向同步、冲突处理、忽略规则与离线队列。
- **desktop-distribution**: 可重复构建、版本元数据、Windows 安装包与更新提示。

### Modified Capabilities

- 无（此前没有桌面端 capability）。

## Impact

- `desktop/`：新增独立 Go 模块、应用装配、原生服务、构建配置与文档。
- `frontend/`：新增桌面环境检测、通知触发点、拖放目标标记与“关于”信息；不改变业务页面结构和路由契约。
- `server/`：无破坏性变更；沿用现有 JWT、CORS 与上传/编译 API。
- 构建与 CI：新增 Makefile 目标和可选桌面构建 workflow；`server/go.mod` 不引入 Wails 依赖。
- 安装包：包含与客户端版本匹配的后端二进制；安装包体积会明显增加，需要评估分发方式。
- 依赖：仅 `desktop/` 引入 Wails v3；前端不新增运行时依赖。

## Out of Scope

- 移动端构建（Wails v3 的 iOS/Android 仍为实验性，且 iOS 需要 macOS + Xcode）。
- 完整离线 CRUD（服务端仍是真相源；游客本地工作区保持现状）。
- UI 重写、主题改版、多窗口编辑。
- macOS/Linux 的签名、公证与商店分发（可构建，不纳入 v1 验收）。
- 自带完整 TeX 发行版（体积通常数百 MB 以上，且需处理许可证与独立更新；v1 继续使用 WASM，未来如做应作为可选组件）。
- 文件关联（双击 `.tex` 直接打开）与系统级“最近文档”集成，留到二期。
