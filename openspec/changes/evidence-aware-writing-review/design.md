## Context

已有`propose_edit`、审批、基准哈希校验、回答依据和`evaluateReviewChecks`。复用而非重建；可靠版本/CAS和证据用途由内容底座提供，章节计划/摘要由组织产物提供。既有产品模型已确认批注、可配置ReviewProfile和事件机会，不把聊天轨迹当作审阅功能。

## Goals / Non-Goals

交付版本安全、可处理的反馈及多维审阅。不是论文评分/查重/AI检测，不认证实验或创新，不执行代码/SSH，不无条件自动调用模型或改稿。

## Decisions

### 1. 三组独立状态

- Run执行：沿用queued/running/completed/failed/cancelled。
- 问题处理：open/deferred/resolved/rejected。
- 适用性：applicable/needs_recheck/stale；运行成功不代表结果仍适用。

`writing_comments`绑定项目、输入快照、局部文本锚点或文档级目标、类别/严重度、理由、依据、处理/适用状态与可选proposal_id；`review_findings`以审阅Run/维度/问题身份关联批注，避免复制一份可独立写入的建议。原文锚点使用阶段B的修订/坐标规则，变动不能盲目套到新文本。

`run_dependencies`/`analysis_dependencies`保存实际读取文本范围、计划/摘要/蓝图字段、规范版本、源版本及查询/过滤范围/代次/候选集合。关联可查、可反向失效；JSON只存类型化范围与查询描述，关键引用/项目边界使用关系约束。

### 2. 用户控制与候选应用

批注显示问题、原因、定位、依据及限制；局部问题可跳转/高亮，全文问题使用文档级目标，不伪造单句锚点。用户可暂缓、拒绝、手工修改后解决、追问或要求复查。需要替换时才复用ChangeProposal显示实际diff；应用仍重验当前修订、依赖、审批和幂等，聊天解释/点击已解决不等于授权写回。

相关范围/研究事实/规范变化使分析待复查；锚点或核心依据不可用则stale。无关局部编辑不全作废；负向覆盖判断依赖检索范围，新相关资料需复查，影响无法判断时保守待复查。旧diff即使分析仍有参考价值也不得直接应用。

### 3. 机会合并而非新增任务平台

`analysis_opportunities`按项目+目标范围+变化类别合并待办，保存最新候选快照、状态/去重身份和原因；运行中的输入不被覆盖，后续变化形成可合并后继。事件来自显式请求、保存/章节完成、资料/计划/规范变更和编译诊断。

项目策略支持manual/focus/severe/assisted，默认manual；非手动模式需用户明确开启并设置授权预算/冷却/并发。事件先成为机会，由现有DeepAgent在权限、预算和实际上下文内选择任务；不以固定字数或聊天轮数判完成。预算不足/专注模式/取消有可见待办或延后状态，不能显示已经检查。机会/确定性工作持久化，单进程worker复用现有生命周期，不引入外部队列；崩溃LLM Run明确中断/失败和幂等重试，不承诺自动续算。

### 4. 规范与Profile

`norm_entries`/`norm_versions`保存来源、版本/日期、适用场景/章节、规则内容、示例及官方要求/通用建议/用户要求/模型建议类型；未知官方性或未提供校方规范不得称“已符合全部校规”。项目采用固定规范包版本，更新先提示选择，不静默替换现有约束。公共内置条目采用到项目时生成可追踪引用/快照，用户私有规范不进入公共库。

ReviewProfile是固定版本配置：复用现有两场景，首批`undergraduate-system-v1`和`intro-paper-v1`可按方法和可用材料调整。维度库覆盖动机/贡献、相关工作/引用、问题/论证链、方法、系统实现、数据/过程、评价设计、结果图表、局限、可复现性、伦理/诚信、结构表达与LaTeX交付；各项明确适用、不适用、规则/模型判据和必要输入，不为不适用维度造问题。

### 5. 审阅执行与结果

在同一稿件/蓝图/采用计划/规范/资料快照运行：先复用确定性结构检查，再做有必要的维度分析，最后汇总去重与冲突；子任务仍是现有Run树，不按维度另造长期服务。章节摘要仅导航，判断问题必须回读相关正文/原始资料。

跨章检查至少包括研究问题—方法、目标—实现材料—测试—结论、结果与摘要/结论范围、术语定义与用法。发现保存关系两端定位、维度、依据、理由、建议和不确定性；无唯一位置时用文档级目标。

每维度状态为checked/findings/insufficient/not_checked/not_applicable/failed（与Run状态独立）；覆盖范围、读取版本、规则结果与模型提示分别呈现。部分失败、预算用尽或资料不足保留已完成结果，但不能宣称全篇通过。模型意见不显示为真实性概率。

## API / UI

项目级comments、opportunities、norms/profiles、review-runs API复用鉴权/信封/CAS约定。写作页侧栏统一承载批注与diff，聊天解释/追问；检查页展示Profile、固定输入、分维度进度、问题列表和复查。现有文件结构检查保留，不因模型不可用而消失；空结果、失败、未检查和不适用分别呈现。

## Verification

固定植入目标遗漏、术语冲突、条件不同、结论越界、过期来源和缺材料；验证两端定位与正文回读、不能仅凭摘要下结论。验证假引用、提示注入、越权、并发编辑/批准、无关/相关变更、搜索范围负向结论、去重机会、manual零自动调用、取消/重启和部分覆盖。通过真实模型案例后再宣称审阅可用，不用规则数量代替学术质量。

## Rollout

先手动批注/规范和确定性结果，再接候选/依赖及手动模型审阅，最后开放可选自动机会。任一步模型或预算不可用时明确限制；保持用户能直接编辑和使用结构检查。
